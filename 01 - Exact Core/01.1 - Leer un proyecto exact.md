# 01.1 - Leer un proyecto exact

> @ref LLP 0000 — sesión de 2026-11-14
> Proyecto de referencia: exact-proyectos/contador (el hola mundo)

## app.contract, bloque por bloque

El corazón del proyecto. Es un DSL (lenguaje propio de exact): dices QUÉ hay, no cómo se dibuja.

```
// Comentario: este archivo es la vista; app.ts responde lo que se pide.

shape Greeting
  text: string
```
`shape` declara un tipo de dato: lo que la capa de datos devuelve. Aquí: un objeto con un campo `text` de tipo string. Los tipos viven en el contrato, no en app.ts.

```
routes nav
  home "/"
```
El mapa de navegación: una ruta llamada `home` en la path `/`. `nav` es el nombre con el que lo consultas (`top(nav)`, `stack(nav)`).

```
component Contador
```
La pantalla. Un archivo puede tener varios componentes; cada uno es una vista reusable.

```
resource greeting = greeting("Contador") as shape Greeting
```
`resource` = un pedido a la capa de datos: llama a la función `greeting` de app.ts con el argumento `"Contador"` y espera un `Greeting` de vuelta. La vista declara QUÉ necesita; app.ts decide CÓMO conseguirlo.

```
state count = 0
action inc
  count = count + 1
action dec
  count = count - 1
```
Estado local y sus escrituras. Regla del DSL: **toda escritura se declara como acción**. `inc`/`dec` son las dos únicas puertas por las que `count` puede cambiar.

```
view
  main testId="root" navigationKey=`${top(nav).id}` width="100%" height="100%"
```
La raíz de la vista. `testId` marca nodos para las pruebas; `navigationKey` ata la pantalla a la pila de navegación.

```
for e in stack(nav) key=e.id
  column navigationKey=`${e.id}` ... position="absolute" inset=0
```
Pinta la pila de navegación: una columna por pantalla en la pila (aquí una sola). Es el andamiaje que `exact new` regala para tener navegación gratis.

```
header ...
  text "Contador" role="heading" aria-level=1 flex=1
```
El encabezado. En cada plataforma se convierte en la barra de navegación nativa (web: barra; iOS: navigation bar). `flex=1` ocupa el ancho restante.

```
scroll id="content" flex=1 min-height=0
  column align-items="center" justify-content="center" gap=16
    text `${count}` testId="count"
    row
      button press=inc ... image "symbol:add"
      button press=dec ... image "symbol:minus"
```
El contenido, centrado. `${count}` interpola el estado en el texto. `press=inc` conecta el botón con la acción. `symbol:add`/`symbol:minus` son íconos de plataforma (SF Symbols en Apple, equivalentes en web). Los nombres de propiedades son de CSS (display, flex, gap, align-items): lo que ya sabes de la web aplica.

Filosofía del DSL: colores y tipografías quedan sin decir, y cada plataforma aporta los suyos. Dices qué, el framework decide el cómo visual.

## app.ts, la capa de datos

```
const sources = { greeting: ([name]) => ({ text: `Hello from ${name}.` }) };
export const answer = (source, args, ...) => sources[source](args, ...);
```
- `sources`: un mapa nombre → función. Cada `resource` del contrato busca aquí su respuesta.
- `answer`: el único punto de entrada: recibe el nombre del recurso y lo enruta.
- `app.contract.d.ts` (generado, no se edita) le da a TypeScript los tipos de las shapes del contrato.

## Los archivos y para qué son

- `app.contract`: la vista, estado, acciones, rutas. El corazón.
- `app.ts`: la capa de datos que responde a los recursos.
- `app.contract.d.ts`: tipos generados del contrato. No editar.
- `app.test.contract`: pruebas declarativas (`tap`, `expect`). Corren en un navegador real.
- `app.json`: metadata de la app: nombre, id (`com.robertflo.contador`), plataformas (`host.web`).
- `exact.mjs`: el corredor de exact; todo comando pasa por aquí (web, test, contract, setup).
- `package.json`: declara bun y las dependencias (sin node ni npm).
- `AGENTS.md` / `CLAUDE.md`: instrucciones para agentes de IA que trabajen en el repo.
- No se versionan: `target/` (builds), `.exact/` (estado local), `node_modules/` (deps de bun).

## El flujo completo

1. Editas `app.contract`.
2. `bun exact.mjs contract build app.contract --json --errors-only` lo valida (el compilador de Contract está escrito en Rust; compila una vez y queda).
3. `bun exact.mjs web` compila el contrato a un módulo ES (~170 KB) y lo sirve.
4. `bun exact.mjs test web` corre las pruebas en Chromium: tap y expect sobre la app real.
5. Las mismas shapes y vistas, después, a iOS/Android sin reescribir nada de la vista.
